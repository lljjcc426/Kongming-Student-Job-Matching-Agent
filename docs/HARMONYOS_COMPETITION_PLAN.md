# 孔明职配鸿蒙高校创新赛任务链

更新时间：2026-07-22

官方入口：[鸿蒙高校创新赛](https://developer.huawei.com/consumer/cn/activity/incentive/C4)。赛程、提交格式和开放能力政策可能变化，提交前必须再次核对官方页面。

## 1. 当前产品决策

首期只深耕互联网与数字技术岗位，覆盖软件开发、AI/算法、数据和产品四类岗位族；暂不扩展医学、法学、教育、财务、蓝领兼职和企业端。

产品主张不是“算出录用概率”，而是帮助求职者回答四个可核验问题：

1. 这是真实、仍可核验的招聘岗位，还是用户导入的 JD，或仅是 AI 生成的职业方向？
2. 岗位每项要求在简历原文中有什么证据，证据是否由用户确认？
3. 哪些硬性条件不满足或仍未知？
4. 哪些简历修改能引用原文证据，哪些缺口只能进入学习清单？

## 2. 已完成架构

| 层级 | 已实现内容 | 可信边界 |
| --- | --- | --- |
| 岗位仓储 | `verified-job`、`imported-jd`、`career-direction` 三类仓储与独立页签 | 三类数据不混排；职业方向不能直接投递 |
| 领域适配 | 互联网与数字技术领域适配器，包含岗位族、技能别名、硬性条件和证据规则 | 不支持领域明确标记为“当前领域未深度支持” |
| 匹配引擎 | 硬性条件门控、逐条要求证据矩阵、证据覆盖率和风险等级 | 覆盖率不是录用或初筛概率 |
| 简历优化 | 原文、建议文本、岗位要求、Evidence ID、风险和逐条接受/拒绝 | 缺失技能不写入当前技能栏，不编造数字与经历 |
| 隐私 | 5 类敏感字段脱敏、会话级外部模型同意、清除本地数据 | 服务端密钥不进入前端；图片外发只作明确兜底 |
| 工作区与求职追踪 | 简历版本、岗位阶段历史、投递版本绑定、今日行动建议 | 简历只在本机工作区保存；服务卡片不保存简历正文 |
| 鸿蒙能力 | 华为账号、Core Vision、Share Kit、Core Speech、Form Kit、相机/麦克风权限 | 核心业务 UI 已切换为 ArkUI/ArkTS 原生；Kit 真机能力单独验收 |
| 性能 | 面试页与 3D AI 助手按需加载，PDF 解析模块动态加载 | 大型视频与模型资源仍占主要安装包体积 |

## 3. 架构任务链

### T0 基线审计（完成）

- HarmonyOS 6.1.1(24)，包名 `cn.kongming.jobmatch`。
- 默认 HAP 只包含 ArkUI/ArkTS 原生页面和系统资源，不包含 React/Vite 静态资源；旧 Web 资源仅通过显式兼容构建进入 HAP。
- 手机、平板、2in1 声明已保留。
- 当前工程没有正式发布签名配置。

退出条件：Web 构建、Harmony 工程静态检查和 HAP 构建可复现。

### T1 可信岗位与领域架构（完成）

- 分离已验证岗位、用户导入 JD 和职业方向。
- 企业官方来源保留来源 URL、验证时间、最近发现时间和状态。
- 模型生成内容剥离投递链接，不冒充真实招聘。
- 首期领域适配器只接受互联网与数字技术岗位。

退出条件：仓储测试、解析器测试、岗位采集器测试和岗位源测试通过。

### T2 证据化匹配与事实约束改写（完成）

- 匹配不再使用文本长度、城市偏好或固定基础分抬高结果。
- 否定表达不能被识别为已掌握技能。
- 未确认简历证据以较弱权重参与判断。
- 每条改写建议必须绑定原文与 Evidence ID，并由用户逐条决定。

退出条件：无关文本不能提高覆盖率，缺失技能不能进入简历技能栏，硬性条件可被单独识别。

### T3 隐私与求职追踪（完成）

- 文本文件和 PDF 文本层可本地读取。
- 鸿蒙安装包优先使用 Core Vision 本机 OCR；本机不可用且用户同意时才调用外部视觉模型。
- 模型调用前统一执行字段脱敏和会话同意检查。
- 求职追踪采用版本化本机存储，记录阶段事件和每日行动。

退出条件：UI 路由测试不出现手机号或邮箱；追踪记录可序列化恢复；职业方向被禁止加入投递追踪。

### T4 鸿蒙构建与原生桥接（本轮完成）

- 华为账号、Core Vision OCR、Share Kit 和 Core Speech 已在 ArkTS 原生服务层接入，默认入口不再使用 JS/native 桥接。
- DevEco Studio 6.1.1.290 已安装到 `D:\DevEco Studio`，ArkTS 编译和 unsigned HAP 打包通过。
- 由于源码路径含中文，构建脚本使用 `D:\KongMing-Harmony-Build` ASCII staging 后回写 HAP。
- 当前模拟器/真机安装截图仍待补齐，旧截图只作为迁移前参考。

退出条件：ArkTS 编译成功，HAP 可安装，Ability 启动成功且画面为最新产品首页。

### T5 原生能力运行收口（进行中）

- Core Speech：TTS、短语音识别、麦克风授权和文本降级已接入；继续补真机权限拒绝、中英混合、后台和网络异常。
- Form Kit：今日行动数据层、卡片页面和 Extension 已接入并在安装信息中注册；继续补桌面动态刷新、杀进程存续和精准跳转。
- 原生文件能力：使用系统文件选择和 Core File Kit，数据直接进入 ArkTS 本机工作区。
- ArkUI 原生化：主工作台已迁移；后续新增岗位详情、账号同步和模型交互都必须继续使用 ArkUI/ArkTS。

退出条件：每个能力均有源码、真机或模拟器记录及失败降级，不以 SDK 存在代替功能完成。

### T6 比赛材料（进行中）

- 基线审计、差距分析、测试计划与报告、已知限制、提交清单。
- 3 分钟演示：本机读取简历 → 真实岗位/导入 JD 分层 → 证据矩阵 → 逐条接受改写 → 本机追踪 → 系统分享。
- 架构图和隐私数据流必须区分本地处理与外部模型处理。

退出条件：材料中的每项“已实现”都有测试、源码或运行证据。
