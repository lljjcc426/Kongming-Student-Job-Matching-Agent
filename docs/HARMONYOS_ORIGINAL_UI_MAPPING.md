# 孔明职配原版到鸿蒙版映射

## 迁移原则

鸿蒙版采用 Web 优先的混合架构，不重新实现一套 ArkUI 产品页：

1. `src/` 和 `public/` 仍是界面、交互和品牌素材的唯一来源。
2. Vite 以相对路径构建，产物同步到 HarmonyOS `resfile` 并随 HAP 离线发布。
3. ArkWeb 只负责承载本地产品；文件、分享、相机、通知等能力再通过最小原生桥接接入。
4. 功能拓展必须落在原有五个模块的信息架构中，不另造一套风格或一级导航。

## 设计基准

鸿蒙版不重新发明一套视觉语言。以下元素以现有 Web 产品为基准：

- 浅蓝科技背景、蓝青渐变主色、白色半透明卡片和细蓝描边。
- 孔明机器人 IP、`孔明职配 / 学生求职智能工作台` 品牌组合。
- 首页、简历解析、岗位推荐、模拟面试、AI 助手五个一级入口。
- 中文主标题配英文功能眉题，例如 `Profile / 学生画像`、`Matching / 岗位匹配工作台`。
- 功能页采用“状态概览 + 工作区 + AI 结论/操作”的信息层次。

原版运行截图保存在 `docs/evidence/web-original-*-desktop.png` 和
`docs/evidence/web-original-home-mobile.png`，作为后续视觉回归基线。

## 功能映射

| 原版模块 | 当前直接复用 | 后续原生拓展位置 |
| --- | --- | --- |
| 首页 | 品牌主视觉、产品说明、三项快捷能力、匹配结果展示 | 与本机简历/岗位草稿状态联动 |
| 简历解析 | 学生画像、识别进度、简历上传、AI Insight | 系统文件选择、草稿持久化、分享/导出 |
| 岗位推荐 | JD Parser、岗位匹配结果、关键词差距 | 官方岗位数据、浏览器分享收集、官网跳转 |
| 模拟面试 | 综合面/技术面/HR 面、数字面试官、回答区与反馈 | 相机/麦克风权限、后台中断恢复 |
| AI 助手 | 上下文提示、快捷问题、对话输入与回答 | 网络状态、授权提示和安全的服务端模型调用 |

## 已验证基线

- HarmonyOS 6.1.1(24) 模拟器可安装并启动本地 HAP。
- 五个一级入口均可切换，孔明 IP、面试室、PDF.js 与 Live2D 资源路径已改为兼容本地包。
- 原有“上传简历文本或图片”控件可直接唤起鸿蒙系统的图库、拍照和文件入口。
- 原有模拟面试摄像头已接入按需授权；同意系统相机权限后可显示本机预览。
- ArkWeb 控制台没有资源 404、CORS 阻断或 JavaScript 运行时错误；仅存在 Three.js 自身的弃用警告。
- 模拟器截图保存在 `docs/evidence/kongming-hybrid-*.jpeg`。

## 信息架构约束

- “真实岗位雷达”属于“岗位推荐”页，不替代原来的岗位推荐模块。
- “隐私”不再占用一级导航；授权状态、数据边界和清除操作放在涉及个人数据的页面内。
- “可解释匹配”属于岗位推荐结果，不再单独占用一级导航。
- 企业端不进入本阶段，产品仍以互联网方向求职者为主。
- 示例内容只能用于解释界面，不得伪装成真实招聘信息；真实岗位必须保留来源与官网入口。
