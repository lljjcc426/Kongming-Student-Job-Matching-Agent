# Issue 开发记录建议

本文用于指导后续在 GitLink Issue 中可选补充 Kongming Student Job Matching Agent 的开发记录。本文只提供建议和模板，不代表这些 Issue 已经存在，也不要求本轮创建 Issue。

## 1. Issue 记录目标

如比赛平台强制要求或团队希望补充平台化开发记录，可通过 Issue 记录以下内容：

- 功能设计。
- 模型接口调用问题。
- 系统优化。
- 技术难点与解决方案。
- 演示材料和提交材料准备。

Issue 记录应服务于评审理解项目开发过程，而不是简单重复 README。

## 5. 技术难点与解决方案类 Issue 建议

### 可记录主题

- PDF 文本层和视觉识别如何切换。
- 模型返回非标准 JSON 时如何修复。
- 多个岗位推荐智能体如何并行执行和去重。
- 模拟面试如何区分综合面、技术面和 HR 面。
- 模型密钥如何避免进入前端。
- 如何整理真实调用日志并脱敏。

## 7. 评审查看建议

建议在 GitLink 仓库中建立以下 Issue 分类或标签：

- `feature`
- `model`
- `bugfix`
- `optimization`
- `docs`
- `submission`
- `security`

建议评审查看顺序：

1. 功能设计类 Issue。
2. 模型接口调用类 Issue。
3. 系统优化类 Issue。
4. 提交材料类 Issue。
5. Commit 历史。

## 8. 注意事项

- 不要伪造不存在的 Issue。
- 不要在 Issue 中贴真实 API Key。
- 不要上传未脱敏简历。
- 不要把后续规划写成已完成。
- Issue 应和仓库代码、README、技术文档保持一致。
