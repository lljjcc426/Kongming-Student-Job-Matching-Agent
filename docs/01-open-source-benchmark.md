# 开源项目参考与能力对比

> 调研目的：对开源项目进行能力拆解，比较其在简历解析、岗位匹配、评分解释、简历优化、交互体验和部署方式上的长处。后续开发不简单复制某一个项目，而是择优吸收多个项目的成熟做法，融合为适合本课题的学生求职匹配智能体。

## 重点参考项目

| 项目 | 类型 | 可参考能力 | 对本项目价值 | 注意事项 |
| --- | --- | --- | --- | --- |
| Resume Matcher | AI 简历与岗位匹配 | 简历解析、JD 匹配、关键词建议、AI 简历改写、PDF 导出、多 LLM Provider、Ollama 本地模型 | 可作为“简历-JD 匹配与优化”核心参考 | 功能面向通用求职者，本项目需强化学生画像和岗位推荐 |
| CV-Matcher | 简历匹配与向量检索 | PDF 解析、关键词抽取、向量相似度、Qdrant 检索 | 可参考向量检索和匹配解释结构 | 需要控制工程复杂度，Demo 阶段可先用轻量化实现 |
| ResumeLM | AI 简历生成器 | Next.js、AI 简历助手、ATS 优化、实时建议 | 可参考现代 Web 交互和简历编辑体验 | 侧重简历生成，岗位搜索和学生画像不足 |
| OpenResume | 开源简历生成与解析 | 浏览器本地存储、简历解析、ATS 可读性、无登录体验 | 可参考隐私友好和简历编辑流程 | AI 能力较弱，需要结合匹配引擎补足 |
| Reactive Resume | 开源简历构建器 | 多模板、实时预览、自托管、隐私优先、AI 写作辅助 | 可参考简历编辑器和导出体验 | 系统较重，直接复用成本较高 |
| AIHawk | 自动化求职 Agent | 岗位搜索、自动化表单、个性化投递材料 | 可参考“求职行动流”的设计，但不建议自动投递 | 自动投递可能带来合规和平台限制风险 |
| Bespoke | 浏览器扩展式简历定制 | 从岗位页读取 JD，生成定制简历和求职信 | 可参考“岗位页到简历优化”的低摩擦流程 | 浏览器扩展不是本项目首选交付形式 |

## 能力模块对比

| 能力 | 现有开源常见做法 | 择优融合方向 |
| --- | --- | --- |
| 简历解析 | PDF/DOCX 解析、文本抽取、JSON 化 | Demo 阶段支持文本粘贴和样例简历，后续接入 PDF 解析 |
| 岗位解析 | 粘贴 JD 后提取技能、职责、学历、经验关键词 | 内置岗位样例 + 支持粘贴 JD，输出岗位画像 |
| 匹配评分 | 关键词覆盖率、语义相似度、LLM 评分 | 使用多维评分：能力、经历、关键词、兴趣、成长潜力 |
| 结果解释 | 缺失关键词、弱项提示、建议改写 | 输出“推荐理由、风险点、优化动作”三类解释 |
| 简历优化 | AI 改写、关键词补充、求职信生成 | 聚焦学生简历：项目经历 STAR 化、技能表达、初筛关键词补齐 |
| 求职行动 | 自动投递或申请追踪 | 不做自动投递，提供投递优先级和行动清单 |

## 对比后的融合结论

1. 核心技术路线应采用“规则评分 + 语义匹配 + LLM 解释”的组合，避免只给出黑箱分数。
2. Demo 需要突出学生场景：专业、课程、项目、竞赛、实习、校园经历等信息应进入画像。
3. 自动投递不是本项目重点，容易引入合规风险；更适合做“投递优先级建议”和“材料优化”。
4. 交互上应采用工作台结构：左侧学生画像，中间岗位匹配，右侧优化建议，便于评委快速理解闭环。
