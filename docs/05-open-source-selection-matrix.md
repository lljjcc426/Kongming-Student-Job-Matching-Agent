# 开源项目能力选择矩阵

## 调研口径

本项目不直接复制某一个开源项目，而是将同类项目拆分为能力模块，对比其成熟做法后择优融合。评估维度包括：

- 简历解析能力
- 岗位解析与匹配评分能力
- 结果解释能力
- 简历优化与材料生成能力
- 学生场景适配度
- 前端交互与部署复杂度
- 合规与安全风险

## 项目对比

| 项目 | 核心定位 | 值得借鉴 | 不适合直接照搬 | 融合建议 |
| --- | --- | --- | --- | --- |
| Resume Matcher | 面向 JD 的简历匹配与定制 | Master Resume、JD 输入、AI 优化、匹配分、关键词高亮、PDF 导出、多模型 Provider | 后端和前端较完整，直接复刻成本高；通用求职者定位不够突出学生场景 | 作为主参考：借“简历-JD 匹配-解释-优化”的完整闭环 |
| OpenResume | 开源简历构建器与解析器 | PDF 简历导入、简历构建、ATS 可读性检查、无登录体验、Next.js + Tailwind | AI 匹配和岗位推荐较弱 | 借“简历解析入口”和“轻量、隐私友好”的产品体验 |
| Reactive Resume | 开源简历编辑与模板系统 | 实时编辑、多模板、拖拽布局、多语言、隐私与自托管表达 | 体系重，模板编辑不是本课题核心 | 借“实时编辑 + 模板预览”的交互思路，不引入完整复杂系统 |
| ResumeLM | AI 简历生成与 ATS 优化 | AI 写作助手、ATS 评分、关键词优化、求职材料管理、现代 Next.js 技术栈 | 数据库、认证、支付等 SaaS 能力对参赛 Demo 偏重 | 借“AI 建议卡片”和“ATS/关键词评分”的呈现方式 |
| AIHawk | 自动化求职 Agent | 岗位搜索、申请流程自动化、求职行动链路 | 仓库已归档；自动投递涉及平台规则、账号安全和合规风险 | 只借“求职流程编排”思路，不做自动投递 |

## 能力模块取舍

| 模块 | 首选参考 | 本项目实现策略 |
| --- | --- | --- |
| 简历输入 | OpenResume、Resume Matcher | 首版支持文本粘贴与样例简历；后续接 PDF/DOCX 解析 |
| 学生画像 | 自研 | 抽取专业、年级、课程、项目、竞赛、实习、技能、兴趣方向 |
| 岗位库 | 自研 + Resume Matcher 思路 | 内置典型校招/实习岗位样例，支持粘贴 JD |
| 匹配评分 | Resume Matcher、ResumeLM | 多维评分：能力匹配、经历匹配、关键词覆盖、兴趣一致、成长潜力 |
| 评分解释 | Resume Matcher | 输出推荐理由、风险点、证据片段、下一步动作 |
| 简历优化 | Resume Matcher、ResumeLM | 生成项目经历 STAR 改写、关键词补齐、技能表达优化 |
| 简历编辑 | Reactive Resume、OpenResume | 首版不做完整简历编辑器，采用“优化建议 + 改写候选”工作台 |
| 求职行动 | AIHawk 思路 | 输出投递优先级、准备清单、面试问题，不做自动投递 |
| 部署 | Resume Matcher、OpenResume 的 Web 应用模式 | 使用 Vercel 部署静态/前端应用，保证公网访问稳定 |

## 初步产品融合方案

本项目首版采用“求职匹配工作台”结构：

1. 左侧：学生画像与简历输入。
2. 中间：岗位推荐与目标岗位选择。
3. 右侧：匹配评分、解释、简历优化建议与行动清单。

核心差异点：

- 从“简历工具”升级为“学生求职决策智能体”。
- 不只回答“这份简历匹配多少分”，还回答“为什么适合、差在哪里、先投哪些岗位、简历怎么改”。
- 评分逻辑可解释，避免只呈现黑箱 AI 结论。
- 聚焦学生真实经历表达，强调课程项目、校园实践、竞赛、实习和求职兴趣。

## 开发优先级

1. 完成静态可运行 Demo：样例简历、岗位库、匹配评分、解释与优化建议。
2. 增加用户输入：粘贴简历文本和岗位 JD。
3. 增加可视化：雷达图、关键词覆盖、岗位优先级。
4. 增加 AI 生成层：接入模型生成更自然的优化建议。
5. 增加简历导出或 Markdown 优化稿。
